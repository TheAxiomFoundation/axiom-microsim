## Finding 1 — SECURITY (required): unvalidated `state` → filesystem path + pickle

`CompareRequest.state` is an unconstrained `str` (axiom_microsim/server.py:259),
passed straight to the PE subprocess (`--state req.state`, server.py:342-343).
`scripts/compute_pe_one.py:110` builds `path = _CACHE_DIR / f"{program}-{state}-{year}.pkl"`,
then `pickle.load(path)` (:114) and a write + `os.replace` (:119-123). A `state`
containing `/` or `../` escapes the cache dir → attacker-chosen pickle.load (RCE
primitive) and file write on a PUBLIC Modal endpoint (CORS `*`). The sim succeeds
for bogus states (mask matches nothing), so the path is reachable.

Fix: validate `state` at the API boundary — accept only `"US"` or a valid 2-letter
uppercase state code (use an existing state-code set in the repo if one exists;
otherwise `^[A-Z]{2}$` plus membership in the standard USPS state/DC set). Return
422 on invalid input (Pydantic field validator on the request models that carry
`state` is fine). ALSO defensively sanitize in `compute_pe_one.py`
`_baseline_run_cached` (reject any state not matching `^[A-Z]{2}$|^US$` before
building the path) so the script is safe standalone.

## Finding 3 — undici headersTimeout vs the 790s client abort

web/src/app/api/compare/route.ts uses fetch with a long AbortSignal, but undici
(Node fetch on Vercel) has a default headersTimeout of 300s that AbortSignal can
only shorten. FastAPI sends headers only when the handler returns, so a >300s
first-run compare may die before the advertised 790/800s unless Modal's ~150s
303-redirect long-polling resets the timer per hop.

Fix: read route.ts and set an explicit undici dispatcher with `headersTimeout`
(and `bodyTimeout`) raised to cover the 790s window — e.g.
`import { Agent } from "undici"` and pass `dispatcher` on the fetch options
(route must run on the Node runtime — verify `export const runtime` / config; if
it's on edge runtime, note that and use the appropriate mechanism). Keep it
minimal. If `undici` isn't a declared dependency, use the ambient one Node
provides via `node:` or add the dependency with bun (repo uses bun for JS).
Verify the web build passes: `cd web && bun install && bun run build` (or the
repo's build script — check web/package.json).

## Finding 4 — unbounded caches + replayed elapsed_seconds

`_COMPARE_CACHE` and `_BASELINE_RESULT_CACHE` grow without bound on a long-lived
container, and cached CompareResponse objects replay the original
`elapsed_seconds` on hits. Fix: bound both with a small LRU (a capped OrderedDict
or similar, ~64 entries), and on a compare-cache hit return a copy with
`elapsed_seconds` reflecting the (near-zero) actual elapsed time of the hit.
